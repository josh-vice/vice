# US-005 — Observable, gated releases

Story schema v1.

As an operator, I need every release to prove the custody boundary, venue routing, build integrity, and failure behavior so that a fast terminal does not become an unsafe terminal.

## Acceptance criteria

- Testnet is the default; mainnet fails closed unless the explicit acknowledgement and a valid builder address are supplied.
- Frontend, account snapshots, candles, subscriptions, and execution use the same network selection.
- No server or gateway source may reference a user/shared Hyperliquid private key.
- CI runs custody preflight, frontend policy/math tests, all Rust tests, and the production frontend build.
- CI also runs separate contract, exact-market/catalog, chaos/reconnect, revenue, mobile, load, and security suites, then starts the full one-command stack and executes browser-surface and live testnet endpoint smoke with process cleanup.
- Client-local telemetry tracks every public-feed receipt through store commit and the next animation-frame-ready callback, plus execution acknowledgement latency, rejection, uncertainty, and reconciliation, without wallet addresses or order contents.
- Release target: receipt-to-store p99 < 5 ms, action-to-signed-dispatch p99 < 10 ms, local processing p99 < 2 ms, and chart/feed frame-ready within one animation frame on the reference desktop. The callback is not compositor-confirmed presentation. Client-observed venue acknowledgement remains p50 <= 250 ms and p99 <= 1,000 ms under normal venue health.
- Any unresolved uncertain execution outcome, account/feed stale state, or failed authoritative reconciliation blocks mainnet promotion.
- `VITE_HL_TRADING_KILL_SWITCH=true` fails closed before local-agent unlock and blocks new place/modify/TWAP/Scale transmissions; cancellation and reconciliation remain available for incident response.
- New placement, modification, and venue-managed algorithm transmissions also require a connected wallet, live authoritative account snapshot, and live selected-market feed. Stale/error/connecting states fail closed before signing; cancellation and reconciliation remain available.
- Complete market discovery is rate-limit aware: Info API requests are bounded and paced, retries are finite, and a failed refresh never substitutes fixtures or destroys the last authoritative catalog. The UI must expose the resulting loading, stale, or error state.
- The catalog now persists only a validated same-network, exact-identity descriptor snapshot after a successful authoritative refresh. A cold start may use that snapshot as an explicitly stale baseline while WebSocket prices and the authoritative refresh converge; invalid, cross-network, or oversized cache entries are ignored and storage failure never affects live startup.
- Runtime verification now records the child launcher exit status and fails before smoke checks if startup aborts. This prevents an occupied-port failure from accidentally testing an unrelated pre-existing service and reporting a false green result. Isolated-port replay passed backend/frontend readiness, smoke, browser-surface checks, and cleanup; the occupied-port replay failed closed as intended.
- Runtime verification now also opens the configured Hyperliquid WebSocket and requires first frames for `allMids`, BTC `l2Book`, BTC trades, and BTC candles. A direct testnet replay received all four channels; this is a live-feed reachability check, not fixture or HTTP-only evidence.
- The selected-market health badge now requires recent mids, order-book, and trade events; a global all-mids heartbeat cannot mask a stopped book or trades stream.
- The direct WebSocket smoke uses separate bounded budgets for critical trading feeds and candle confirmation, preserving a truthful candle requirement without treating venue-side candle queueing as a dead order-book/trades connection.
- Warm-catalog startup preserves the explicit `STALE` state through the in-flight authoritative refresh instead of relabeling cached identities as merely `SYNC`; `markets.test.js` covers the state boundary.
- HIP-3 asset IDs preserve the official sparse `perpDexs` array index; null DEX entries are not compressed before applying the venue formula.
- The live registry consumes Hyperliquid all-DEX perp and spot context streams, updates metrics in place by exact asset identity, and does not use volume-sorted registry position as a routing or context index.
- A partial catalog is explicitly degraded: core/spot markets remain usable when an individual HIP-3 DEX request fails, but the UI exposes that the market universe is incomplete and continues bounded refreshes. A complete catalog is only reported live after all requested sections succeed.
- Market WebSocket close and subscription failure signals mark the feed stale and trigger one debounced, generation-safe resubscription for book, trades, candles, all-mids, all-DEX perp contexts, and spot contexts. The HTTP baseline remains visible during recovery and chart state is not reset by the recovery path.

## Operational contract

- Persona: Release engineer promoting a non-custodial trading build through testnet, canary, and mainnet gates.
- Preconditions: Static release suite, runtime smoke/browser evidence, security/preflight checks, current latency evidence, and documented funded-testnet story results.
- Success behavior: A release is reproducible, observable, kill-switchable, and promoted only when every required gate is green.
- Failure behavior: Missing evidence, stale/uncertain execution, unsupported configuration, failed preflight, or degraded critical feed blocks promotion.
- Reconnect behavior: Runtime verification and release replay prove clean service restart, feed recovery, and no stale process/port ownership.
- Restart behavior: One-command startup detects conflicts, exposes service identity, waits for readiness, runs verification, and cleans up deterministically.
- Stale/offline behavior: Release status distinguishes static pass from runtime, funded, and measured-latency evidence; missing evidence never becomes a pass.
- Custody expectations: Preflight rejects shared signing-key paths, hosted mutations, unsafe origins, and mainnet configuration without explicit acknowledgements.
- Latency expectations: Enforce receipt/store, frame-ready, local processing, and action/signed-dispatch budgets using versioned client telemetry; synthetic samples cannot certify production.
- Telemetry: Retain release gate results, service health, feed/account SLOs, command uncertainty, reconciliation, builder/referral attribution, and rollback signals without secrets.
- Linked tests: `preflight.mjs`, `release-gate.mjs`, latency boundary/gate tests, launcher tests, all category suites, `bun run dev:verify`, and CI workflows.
- Funded-testnet evidence: Repeated US-002/003/004 story passes, low-notional allowlisted pilot, builder/referral reconciliation, and incident/rollback rehearsal are required before mainnet.
- Given any required gate lacks authoritative evidence, when a release is evaluated, then promotion fails closed and names the missing evidence.
