# US-011: Persistent conditional automation without custody compromise

Story schema v1. Status: In progress.

As a trader who cannot babysit a browser tab, I want conditional and long-running orders to survive tab and device lifecycle to the maximum extent possible without giving anyone custody, so that Vice answers Insilico's Cortex while keeping the non-custodial boundary intact.

## Acceptance criteria

- The product explicitly documents the automation persistence ladder: (1) venue-native orders (stops, TP/SL, native TWAP) survive everything and are preferred whenever a venue primitive exists; (2) local algo jobs persist on the same device; versioned direct Scale, conditional ladders, Chase, trailing, Iceberg, Ping-Pong, adaptive/VWAP, POV, and break-even jobs recover complete pending child dispatches from the journal. Versioned OCO and Swarm jobs recover each proven sequential leg but pause incomplete work pending an explicit exact-market resume. Older records pause for child-command review after restart; (3) an optional user-run local orchestrator (self-hosted, holding only the user's own agent key) may run jobs headlessly; hosted Vice-side signing remains prohibited.
- Every client-side algorithm and conditional order states its persistence class in the ticket before submission; no strategy implies server persistence it does not have.
- Conditional triggers reach parity with Cortex trigger types: price cross, candle close, candle volume, time-based, and synthetic pair-price triggers, evaluated from live feeds with the existing conditional-ladder state machine pattern.
- Dead-man `scheduleCancel` protection remains the default answer for "what if my tab dies mid-strategy," armed per US-004 semantics.
- If the self-hosted orchestrator ships, it reuses the same journaled execution client, certification flags, and reconciliation rules; a divergent second execution path is prohibited.
- Given a running local algo and a closed tab, when the trader reopens Vice on the same device, then the job resumes only after authoritative reconciliation, and any venue-side dead-man cancellation that fired in between is reported truthfully.

## Operational contract

- Persona: Trader running multi-hour strategies who cannot guarantee a continuously open tab.
- Preconditions: Per-strategy certification; explicit persistence-class disclosure acknowledged; dead-man policy selected where applicable.
- Success behavior: Strategies run under their declared persistence class; venue-native primitives are chosen automatically when equivalent.
- Failure behavior: A trigger source going stale pauses evaluation with visible state; nothing fires on cached prices; orchestrator unavailability degrades to device-local semantics.
- Reconnect behavior: Trigger evaluation re-arms only from live feeds; missed crossings are reported as missed, never executed retroactively.
- Restart behavior: Persisted jobs restore with progress and reconcile every child before advancing (US-004 semantics), on both browser and orchestrator runtimes.
- Stale/offline behavior: All conditional evaluation suspends on stale inputs; the dead-man switch provides the offline safety floor.
- Custody expectations: No hosted Vice signing ever; the optional orchestrator is user-operated, holds only that user's agent key, and is distributed as auditable open configuration.
- Latency expectations: Trigger-evaluation-to-dispatch stays within the local processing p99 <2 ms and signing p99 <10 ms budgets on the reference device.
- Telemetry: Browser-local trigger telemetry persists the device-local persistence class, runtime, trigger type, and fire/miss/pause counts only. It never stores a market, threshold, strategy value, account, wallet, or order. An orchestrator runtime remains unavailable.
- Linked tests: trigger evaluation tests per type, persistence-class disclosure surface tests, orchestrator/browser shared-boundary contract tests, missed-crossing rearm tests.
- Funded-testnet evidence: Each trigger type requires funded fire/miss/reconnect/restart evidence; the orchestrator additionally requires kill/resume and divergence-detection evidence before any exposure.

## Evidence log

- Persistence disclosure slice: the order ticket now states the actual persistence class before submission. Limit, market, stop, stop-limit, bracket, and native TWAP orders state that the venue manages them after acceptance. Certified local algorithms state that they persist only on the trader's device, never on Vice servers, and reconcile before resuming after reopen. Automated coverage: `src/lib/components/orderPersistenceDisclosure.test.js`. A self-hosted orchestrator, trigger-lifecycle browser proof, and funded lifecycle evidence remain open.
- Trigger-engine safety slice: `execution/conditionalTriggers.ts` provides one pure, runtime-neutral state machine for price-cross, candle-close, candle-volume, time, and synthetic-pair triggers. It accepts only exact live source identities, arms before an edge, pauses on stale input, suppresses duplicate candles, and records a possible stale-period crossing as missed rather than dispatching late. Conditional ladders now expose price-cross, completed-candle close, completed-candle volume, future local-time, and synthetic-pair choices. Candle triggers require the selected exact market and saved interval to remain active, plus a separately live authoritative candle stream; the chart's trade-derived fallback cannot arm or fire them. A time trigger rejects a due or invalid time at creation, does not backfill after restart or a clock outage, and still requires live exact selected-market data before it can dispatch. A pair trigger persists both exact market identities and uses only their fresh all-mids values; a missing or stale leg pauses it rather than using a cached price. Ratio thresholds remain positive; spread thresholds may be signed but must be finite. A fired edge is persisted before any order attempt. Before its Scale dispatch, the job also persists that batch's exact command ID; restart adopts complete journaled children and pauses a missing or unresolved command rather than dispatching again. Coverage: `execution/conditionalTriggers.test.js`, `execution/conditionalLadderMath.test.js`, `execution/conditionalLadderSurface.test.js`, `execution/scaleDispatchRecovery.test.js`, and `hl/subscriptionsIdentity.test.js`. This is statically verified only; the user-run runner and all conditional-ladder funded lifecycle evidence remain open, and all conditional ladders remain certification-gated.
- Automation telemetry slice: `execution/automationTelemetry.ts` persists a bounded browser-local count for each trigger source and fire/pause/miss outcome. The Algorithms panel exposes aggregate device-local outcomes; privacy mode hides the panel. The record contains neither market/account identity nor strategy/order values. Coverage: `execution/automationTelemetry.test.js` and `components/algoControlSurface.test.js`. This is local static evidence, not an orchestrator or funded lifecycle certification.
- Browser smoke on 2026-07-28 loaded the local testnet terminal with live public BTC data, opened Algorithms, displayed the device-local trigger telemetry panel, and reported no browser console errors. It did not connect a wallet, unlock an agent, arm a trigger, or submit an order. This is partial browser evidence only; trigger fire/miss/reconnect/restart and funded lifecycle proof remain open.
