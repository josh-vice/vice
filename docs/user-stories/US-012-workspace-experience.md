# US-012: Dockable workspace, power input, and the dither design language

Story schema v2. Status: In progress (dither stale/depth language and privacy mode partially implemented).

As a daily driver of the terminal, I want a fast, saved workspace with power-user input (programmable hotkeys, a chainable CLI, layouts, privacy mode) and a coherent visual language, so that Vice matches professional terminal flexibility without creating a second execution system.

## Acceptance criteria

- The desktop workspace is owned by `WorkspaceHost` over Dockview. It provides dockable, resizable, tabbed, floating, and popout-capable panel groups while preserving exact shared market/account stores. Default, Chart Max, and Data Dense remain named local starting layouts; layouts serialize locally with a schema version and corruption fallback. No layout stores private account snapshots, credentials, or signing authority.
- A trader can open multiple independently pinned, read-only market snapshot panels. Each panel persists an exact `marketKey`, receives only public registry quote/context fields, and can explicitly switch the shared workspace market. Explicit cyan, amber, and violet link groups may synchronize only an exact public market/timeframe pair across snapshot panels. A snapshot owns no book, chart, account, or execution context. Full linked, independently fed chart/book/ticket contexts remain a separate requirement.
- Hotkeys become programmable: every existing action (side, sizing presets, timeframe, arm/disarm, CLI, panel focus, flatten/reverse when certified) is bindable, with conflict detection and a discoverable cheat-sheet overlay.
- The CLI gains chaining (`;`), repeat, aliases, and user variables (e.g. `$size`, `$entry`) while preserving exact-identity resolution and certification gating for every dispatched command; chained commands stop at the first failure with per-step results.
- Privacy mode hides balances, sizes, and PnL globally; sound alerts (fills, algo events, alerts) are configurable with a master mute (shared with US-008).
- The ordered-dither design language is applied consistently: dithered depth bars in the book, dither stale veils on any non-live data surface, and dither rules in panel headers; dither density communicates state (light = texture, half-tone = stale, heavy = halted/disabled) and is documented as a design token set in `vice-terminal/src/lib/styles/dither.css`.
- Dither and animation effects never run per-tick work on the data hot path; they are pure CSS mask/compositor effects with zero JavaScript cost and do not regress the one-frame frame-ready budget.
- Dormant surfaces (options, RFQ, strategy builder, trollbox, DEX comparison) remain development-only scaffolding behind the fixture flag. OptionsChain is deliberately absent from the public component barrel; no dormant surface may be added to production navigation without authoritative data, an explicit user story, and its own release gate.
- US-012-AC-001: Given a trader with a custom hotkey bound to a certified action, when the key fires while an input is focused, then the hotkey is suppressed exactly as the current global handler suppresses built-ins.

- Action IDs: story.us-012

## Operational contract

- Persona: Daily active trader living in the terminal across long sessions, often streaming.
- Preconditions: Local preference storage available; certified actions only are bindable/dispatchable; feeds live for any action requiring them.
- Success behavior: Layouts, bindings, aliases, and visual state apply instantly and persist; all input paths route through the same shared, gated actions as pointer UI.
- Failure behavior: Broken or conflicting bindings are rejected at definition time; a chained CLI step failure halts the chain with explicit per-step outcomes.
- Reconnect behavior: Workspace state is purely local and unaffected; any action fired during reconnect follows the shared fail-closed execution guards.
- Restart behavior: Layouts, bindings, aliases, public link contexts, privacy and sound preferences restore from local storage without restoring any account state.
- Stale/offline behavior: Stale surfaces show the dither veil plus their textual health label; input paths targeting stale markets fail closed with explicit errors.
- Custody expectations: No change; workspace features never introduce new transmission or signing paths.
- Latency expectations: Hotkey/CLI dispatch adds no measurable overhead to the action-to-signed-dispatch p99 <10 ms budget; dither styling adds zero JS on the frame-ready path.
- Telemetry: Record preset/binding/alias usage counts, cheat-sheet opens, and privacy-mode adoption without recording bound values or command contents.
- Linked tests: binding conflict/suppression tests, CLI chain/alias/variable parser tests with certification-gate coverage, preset persistence tests, dither-utility CSS regression checks in the browser surface suite.
- Funded-mainnet evidence: Not execution-bearing beyond existing gates; hotkey/CLI-dispatched certified orders reuse each order type's own funded evidence, plus one funded chained-command lifecycle proving stop-on-failure.

## Evidence log

- Privacy slice: a browser-local preference masks navbar account and wallet values, ticket margin summaries, and all private chart/account-panel rows. Hiding the view never mutates the account stores, signing, or reconciliation state. Automated coverage: `src/lib/privacyMode.test.js`; browser and streaming proof remain required.
- CLI chain/repeat slice: semicolon-separated commands now run in order through the existing guarded executor. `repeat <1-10> <command>` re-enters that same executor for every iteration, so aliases, exact market identity, and certification gates are applied each time. Empty steps, malformed/out-of-range counts, and nested repeats are rejected; the first error stops the remaining chain or iterations with per-step results. Automated coverage: `src/lib/cli/executor.test.js`; browser and funded lifecycle proof remain required.
- CLI preference slice: aliases and `$variables` are bounded local preferences. Expansion happens before the existing parser and certification gates, rejects malformed names and oversized values, and never creates a second dispatcher. Automated coverage: `src/lib/cli/preferences.test.js`; browser and funded lifecycle proof remain required.
- Dockview workspace-host slice: the desktop now mounts existing Chart, Markets, Depth & tape, Order ticket, and Account activity components through a client-only `WorkspaceHost`. Dockview owns docking, resize, tab, floating, and popout-capable presentation only; panel components retain their shared stores and execution boundaries. Layouts save by named local preset with schema version `1`; malformed or incompatible saved data is discarded before a default layout is created. `src/lib/workspaceLayout.test.js` and `components/workspaceHostSurface.test.js` cover the persistence and boundary. In-app browser verification loaded the live Dockview Chart panel, changed Chart Max then Default, reloaded the app with the Default arrangement intact, then floated Chart and reloaded with the float restored. Popout behavior, redock, crosshair links, multi-market instances, and hide/show frame-memory measurements remain open.
- Hidden-panel suspension slice: `WorkspaceHost` now configures Dockview's `onlyWhenVisible` renderer by default. Inactive tabs no longer retain a live render surface; shared worker feeds, stores, account state, and execution journals stay outside the workspace engine, so visibility cannot change data correctness or an active command. Static coverage: `components/workspaceHostSurface.test.js`. Browser frame/memory measurements across repeated hide/show cycles remain required.
- Panel visibility slice: watchlist, book/tape, ticket, and account-panel visibility each persist locally. The chart stays present, and Chart Max still overrides its side columns. Automated coverage: `src/lib/workspacePreset.test.js`; browser visual and persistence proof remain required.
- Non-destructive visibility lookback: changing a panel choice now adds or removes only that Dockview panel. It does not clear or recreate the trader's other dock groups, tabs, sizes, or saved arrangement. Static coverage: `components/workspaceHostSurface.test.js`; drag/dock persistence after a visibility change still requires browser proof.
- Floating and popout workspace slice: every Dockview tab now has `Float panel` and `Pop out panel` context actions. Floating groups are bounded to the terminal viewport, use a dedicated titlebar drag handle, and keep the existing shared market, account, and execution stores; neither action can create a second signing or feed path. Popouts use the static, same-origin `/popout.html` shell, which runs no Vice application script: Dockview moves the existing panel container into it. Its CSP blocks scripts, network connections, forms, frames, and non-local active content; it allows only local or copied Dockview styles. Dockview keyboard navigation is enabled for tab/group movement and accessible docking. Static coverage: `components/workspaceHostSurface.test.js`. On 2026-07-28, the local testnet terminal opened the Chart tab menu, floated Chart, reloaded, and restored one floating dialog with one titlebar and Chart tab. A repeat on 2026-07-29 reached live public data, floated Chart, and restored the dialog after reload with account sync off and trading disabled. The embedded browser blocked opening a new window, so it did not test popout behavior. This proves the local floating interaction and persistence, not popout behavior, redock, multi-market instances, account switching, execution, or funded behavior.
- Read-only multi-market snapshot slice: any Dockview tab can open an `Open current market snapshot` panel. The panel ID and layout parameter retain the exact `marketKey`; its view looks up that key in the public registry and fails closed when the catalog no longer carries it. It never imports an order book, account state, or execution helper. Static coverage: `components/marketSnapshotSurface.test.js` and `components/workspaceHostSurface.test.js`. On 2026-07-29, the local testnet terminal opened a `BTC-USD-PERP snapshot`, reloaded it, and restored exact `perp:BTC` / `BTC` identity with public quote/context fields and only a `Use in shared workspace` button. No wallet or order action was used and browser errors were empty. This is a read-only browser verification, not linked charts/books/tickets, multi-account state, or funded behavior.
- Public link-context slice: a workspace tab can explicitly open and set a cyan, amber, or violet public link. The local schema stores only exact `marketKey`, timeframe, and update time; all snapshots in that group follow the same public context, and a missing linked market stays unavailable rather than falling back to a display-symbol match. Runtime input and local storage are sanitized to that three-field shape before retention, so a stray account, credential, or other extra key cannot enter the local link store. The link is visibly labeled and may explicitly select the shared workspace market, but it never creates a book, chart, account, signing, or execution path. Coverage: `src/lib/workspaceLinks.test.js`, `components/marketSnapshotSurface.test.js`, and `components/workspaceHostSurface.test.js`. On 2026-07-29, the local terminal's Chart menu exposed all three groups; selecting cyan opened `BTC-USD-PERP · cyan` on live public data while account sync remained off and trading remained disabled. This proves the one-panel public action, not multi-panel synchronization, crosshair propagation, independent feeds, account contexts, or linked execution.
- Workspace bundle lookback: Dockview remains a client-only lazy chunk with an 80 KiB gzip release budget. The current production build measured 73,959 gzip bytes. `scripts/bundle-budget.test.mjs` rejects a missing chunk or a static-size regression. This is a download-budget guard, not a substitute for browser frame, memory, or interaction latency evidence.
- Dither regression lookback: `styles/ditherSurface.test.js` now guards the CSS-only mask primitives and their use on chart, book, and tape. The test rejects animation keyframes and checks that stale decoration remains pointer-inert and paired with a textual feed health label. It is static coverage only; compositor and frame-time measurements remain required.
- Hotkey slice: configurable bindings now cover the current global buy, sell, size-preset, and CLI actions. The Navbar hotkey menu is both a compact cheat sheet and binding editor; it rejects duplicate bindings. Global dispatch uses canonical bindings and suppresses shortcuts in inputs, selects, textareas, and contenteditable regions. Automated coverage: `src/lib/hotkeys.test.js`; browser interaction proof and bindings for remaining certified actions are still required.
- Timeframe hotkey slice: chart 1m, 5m, 15m, 1h, 4h, and 1D selections are now configurable (default `Alt+1` through `Alt+6`) and call the same `setChartTimeframe` action as the chart controls. Automated coverage: `src/lib/hotkeys.test.js` and `src/lib/hl/subscriptionsIdentity.test.js`; browser interaction proof remains required.
- Click-placement slice: chart click placement can now be armed or disarmed through a configurable `A` shortcut. It changes only the existing local mode; any later chart order still goes through the chart's established identity, consent, and execution guards. Automated coverage: `src/lib/hotkeys.test.js`; browser interaction proof remains required.
- Panel-focus slice: configurable `Alt+C`, `Alt+B`, `Alt+T`, and `Alt+P` bindings focus the chart, book/tape, order ticket, and account panel. They are non-trading actions, use keyboard-visible focus rings, and remain suppressed while typing. Automated coverage: `src/lib/hotkeys.test.js`; browser interaction proof remains required.
- Workspace recovery lookback (2026-07-29): a persisted floating snapshot could displace the core grid on restore, and the default insertion sequence could collapse Chart, Depth & tape, or the ticket to an unusable sliver. Layout schema `2` discards that incompatible state. The PANELS menu now exposes `Reset this layout`, which removes only the selected local layout and rebuilds it. Floating/popout arrangements are not saved as a primary layout. The default constructor applies measured post-layout sizes for Markets (280px), Chart (available width after side columns), Depth & tape (270px), Order ticket (320px), and Account activity (250px). In a live public testnet browser at a 1280px workspace, the reset measured 280/410/270/320px top-row widths with a 250px activity row; the wallet remained disconnected and all trade controls remained disabled. Coverage: `workspaceLayout.test.js`, `workspacePreset.test.js`, and `components/workspaceHostSurface.test.js`. This supersedes the earlier floating-layout restoration behavior; drag/redock/popout proof remains open.
