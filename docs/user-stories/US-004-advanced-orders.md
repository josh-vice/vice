# US-004: Reliable advanced orders

Story schema v2.

As an advanced trader, I want every exposed strategy to have explicit lifecycle semantics and authoritative venue reconciliation so that automation never behaves like a decorative preset.

## Current acceptance boundary

- Native TWAP uses Hyperliquid's venue-managed TWAP action, clamps duration to 5–1440 minutes, and returns the authoritative TWAP ID.
- Adaptive TWAP and VWAP are implemented as local, persisted child-order state machines. They derive deterministic slice sizes from public trade flow, place exact-market post-only children at the live book, reconcile fills before advancing, pause on unexplained child disappearance, and support pause/resume/cancel/emergency stop. Each versioned child persists an exact command ID before signing; restart adopts one proven journaled child, records rejection, and pauses unresolved placement rather than sending a replacement. Older local records pause for review. Both remain hidden until their independent funded-testnet certification flags are enabled.
- Volatility sizing is implemented as a separate certified sizing control. It computes ATR from authenticated Lightweight Charts history, derives an ATR-based stop and risk size from authoritative equity/margin, clamps to venue precision, and remains unavailable unless `VITE_HL_CERTIFIED_VOLATILITY_SIZING=true`.
- POV is implemented as a separate persisted local state machine. Each child is capped at the configured percentage of recent public trade volume, waits when flow is insufficient, uses exact-market post-only placement, reconciles fills before continuing, pauses when a child disappears without an authoritative fill, and supports dead-man/lifecycle controls. Each versioned child persists an exact command ID before signing; restart adopts one proven journaled child, records rejection, and pauses unresolved placement rather than sending a replacement. Older local records pause for review. It remains hidden until `VITE_HL_CERTIFIED_POV=true`.
- Break-even protection is implemented as a separate persisted exact-market state machine. It waits for a favorable mark-distance trigger, then places a reduce-only stop at entry plus the configured offset, reconciles the child authoritatively, and supports pause/resume/cancel/emergency and dead-man behavior. Its versioned protection child persists an exact command ID before signing; restart adopts one proven journaled child, records rejection, and pauses unresolved placement rather than sending a replacement. Older local records pause for review. It remains hidden until `VITE_HL_CERTIFIED_BREAK_EVEN=true`.
- Maker routing is implemented as a separately certified local-signer path. It derives a venue-precision price from the live best bid/ask plus a non-negative offset, rejects missing/stale books and crossing prices before signing, and submits only Hyperliquid post-only (`Alo`) orders with the exact selected market identity. It remains hidden until `VITE_HL_CERTIFIED_MAKER=true`.
- Conditional ladders are implemented as persisted exact-market jobs. The ticket explicitly selects stop or take-profit trigger semantics; jobs remain inert until that configured trigger is reached, then delegate to the journaled atomic Scale path, retain all child IDs, reconcile fills/open orders after restart, and expose pause/resume/cancel/emergency behavior. Before that Scale batch is sent, the job persists its exact command ID; restart adopts complete journaled children, rejects a journaled failure, and pauses any missing or unresolved record rather than sending a duplicate batch. They remain hidden until `VITE_HL_CERTIFIED_CONDITIONAL_LADDER=true`.
- Scale builds 2–100 deterministic levels spanning both selected boundaries, preserves requested total size before venue rounding, and submits the ladder atomically with unique cloids.
- Post-only scale ranges that cross the current spread are rejected before signing.
- Scale transport uncertainty reconciles every cloid before reporting failure.
- Internal Chase orchestration now persists signed child-order IDs, supports pause/resume/cancel/emergency stop, and an explicit opt-in account-wide dead-man switch. Before every child placement it persists an exact command ID; restart adopts one complete journaled child, rejects a journaled failure, and pauses an incomplete record rather than sending a replacement. It remains hidden from the production selector and CLI until funded-testnet certification.
- Internal OCO orchestration now persists independent take-profit and stop-loss child IDs, cancels the sibling after an authoritative fill, pauses on unexplained child disappearance, and exposes pause/resume/cancel/emergency controls. Each versioned sequential leg persists its own exact command ID before signing; restart adopts only proven journaled legs, fails a journaled rejection, and pauses incomplete pairs. It never submits a missing protection leg automatically after restart: the user must select the exact market and explicitly resume. Older local OCO jobs pause for review. It remains hidden until funded-testnet certification.
- OCO now accepts the same optional account-wide `scheduleCancel` dead-man protection as the other local algorithms: it is armed before the first child, refreshed after both children are present, cleared only after a reconciled completion or normal cancellation, and replaced with a short emergency window after an emergency stop. If partial placement leaves sibling cancellation uncertain, the job pauses for reconciliation instead of claiming cleanup succeeded.
- Internal trailing-stop orchestration now persists the monotonic extreme, replaces only when the trigger improves, reconciles child fills/disappearance, and supports pause/resume/cancel/emergency controls. Each versioned job persists an exact child command ID before signing; restart adopts exactly one journaled child, records a journaled rejection, and pauses an unresolved child rather than sending a replacement. Older local trailing jobs pause for review. It remains hidden until funded-testnet certification.
- Internal Iceberg orchestration now persists exact market identity, parent/child IDs, remaining and filled size, submits signed display-size slices sequentially, reconciles each child against authoritative open orders and fills, and supports pause/resume/cancel/emergency controls. Each versioned job persists an exact slice command ID before signing; restart adopts exactly one journaled child, records a journaled rejection, and pauses an unresolved slice rather than sending a replacement. Older local Iceberg jobs pause for review. It remains hidden from the production selector and CLI until funded-testnet certification.
- Internal Swarm orchestration now persists exact market identity, deterministic post-only child prices, child IDs, slice progress, reconciliation state, pause/resume/cancel/emergency controls, and optional dead-man protection. Each versioned ladder child persists its exact command ID and index before signing; restart adopts one proven child and pauses before remaining slices until the user selects the exact market and explicitly resumes. Missing, ambiguous, and rejected children never cause a replacement. Older local Swarm jobs pause for review. It remains hidden from the production selector and CLI until funded-testnet certification.
- Internal Ping-Pong orchestration now persists exact market identity, alternating leg state, cycle progress, child IDs, authoritative fill gating, pause/resume/cancel/emergency controls, and optional dead-man protection. Each versioned leg persists an exact command ID before signing; restart adopts exactly one journaled child, records rejection, and pauses unresolved placement rather than sending a replacement. Older local Ping-Pong jobs pause for review. It remains hidden from the production selector and CLI until funded-testnet certification.
- All exposed client-side algorithms arm the optional account-wide dead-man switch before their first child placement and re-arm it before subsequent child placements, closing the crash window between signing a child and scheduling cancellation.
- Normal cancellation clears that algorithm's dead-man switch after child cancellation; emergency stop intentionally leaves the venue switch active so an interrupted session still has a short safety window.
- OCO take-profit and stop-loss children are submitted on the opposing side of the entry so they reduce/close exposure rather than add to it.
- Break-even and trailing-stop children use the same opposing-side invariant; a long entry exits with a sell and a short entry exits with a buy. `execution/protectionSide.test.js` guards this safety boundary.
- Bracket TP/SL placement is explicitly gated behind `VITE_HL_CERTIFIED_BRACKET`. The implementation targets Hyperliquid's authoritative `positionTpsl` grouping so exit quantity follows the live position through partial entry fills, reconnects, and subsequent position-size changes; fixed-size `normalTpsl` is not used. The bracket remains unavailable until funded-mainnet evidence proves entry, partial fill, protection creation, and restart recovery.
- OCO user cancellation now remains paused for reconciliation when any known child cancel or dead-man clear is rejected/uncertain; it never reports a terminal cancelled state from a partial acknowledgement.
- Traders can save, load, and delete up to 32 account/network-scoped order presets locally. Presets capture order intent and advanced configuration only; they never bypass exact market identity, current account state, venue precision, or execution safety checks. Wallet switch and disconnect clear the active preset view.
- The order ticket's amount unit switch is functional: traders can enter venue base size or quote/USD notional, with conversion based on the current authoritative market price before the existing precision and margin checks.

## Operational contract

- Persona: Advanced trader running a certified local algorithm or protection workflow.
- Preconditions: Explicit per-type certification flag, unlocked local agent, live exact market/account/public-flow inputs, persisted job identity, and dead-man policy where applicable.
- Success behavior: Each exposed strategy persists children, progress, errors, lifecycle state, and authoritative venue IDs while advancing only after reconciliation.
- Failure behavior: Partial child/dead-man acknowledgement, unexplained disappearance, stale flow, or transport uncertainty pauses the job and requires reconciliation.
- Reconnect behavior: Restore the unlocked account scope, reconcile every child and dead-man state, and resume only from an authoritative state. Strategies without complete child-command recovery pause instead of resuming automatically.
- Restart behavior: Persisted jobs remain visible with progress/error state; no child is replayed without cloid/order-state proof.
- Stale/offline behavior: Advanced jobs pause and remain explicitly degraded when market/account/public-flow inputs are stale or unavailable.
- Custody expectations: All child mutations are browser-local signed Hyperliquid actions; unsupported strategies remain hidden and hosted execution routes remain unavailable.
- Latency expectations: Child scheduling and local state transitions stay within local processing/action dispatch budgets; venue timing is recorded independently.
- Telemetry: Record strategy type/certification, child IDs, slice progress, dead-man status, pause reason, reconciliation result, and per-child latency without private keys.
- Linked tests: `execution/*Surface.test.js`, state/math/journal/reconcile tests, CLI parity, Rust contracts, chaos/load suites, and funded-testnet lifecycle tests.
- Funded-mainnet evidence: Every exposed strategy requires funded entry/partial-fill/reconnect/restart/cancel/error evidence before its flag is enabled; bracket requires position-TPSL proof.
- US-004-AC-001: Given a certified running strategy, when a child disappears without an authoritative fill, then the strategy pauses and never creates a replacement child until reconciliation succeeds.
- Latest duplicate-prevention slice: every local algorithm timer now serializes asynchronous ticks per persisted job. A slow venue acknowledgement cannot overlap the next interval and submit a second child before the first child identity is persisted. The shared tick guard has direct concurrency tests and every advanced state-machine module is covered by a source-boundary safety test.
- Latest capability-clarity slice: the ticket now reports how many implemented advanced strategies remain locked and explains that they are available for inspection in the order-type menu but require funded-testnet lifecycle and reconnect certification before selection. The quick bar and CLI remain certification-gated. `execution/advancedOrderSurface.test.js` guards the visible status and complete catalog.
- Latest lifecycle-control slice: the compact Algorithms panel now passes every non-specialized row's persisted strategy type directly to its pause, resume, cancel, and emergency-stop dispatcher. The dispatcher is explicit for Iceberg, Swarm, adaptive TWAP/VWAP, POV, break-even, conditional ladder, Scale, and Ping-Pong; an unknown type fails rather than being treated as another strategy. A failed conditional ladder cannot display Resume because its persisted fired edge requires reconciliation or a new explicit job, while a paused stale/missed ladder may be manually re-armed. `components/algoControlSurface.test.js` guards this control boundary.
