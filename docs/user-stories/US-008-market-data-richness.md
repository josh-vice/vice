# US-008: Market-data richness without staleness

Story schema v1. Status: In progress.

As an active trader, I want funding, open interest, liquidations, price alerts, and a configurable order book alongside the existing feeds, so that Vice matches Insilico's data surface while keeping every value provably live.

## Acceptance criteria

- The existing market stats strip (spread, funding/hour, 24h volume, open interest, index, mark) gains a funding countdown and per-value health labeling: no stat is ever rendered from a stale asset context without labeling.
- The trade tape flags liquidation events distinctly and supports a minimum-notional filter; filtered state is visible so an empty tape is never mistaken for no trades.
- Traders can set local price alerts (cross above/below) per market; alerts fire from the live mid/trade stream with sound and visual notification, persist locally, and state plainly that they exist only while the app is open.
- Order book precision grouping (nSigFigs) and level depth are user-adjustable; regrouping is a resubscription with explicit connecting state, not a client-side approximation presented as venue data.
- Fill/order events produce optional sound notifications with a global mute; sounds never substitute for the visual authoritative state.
- A privacy mode hides balances, position sizes, and PnL across all account surfaces for streaming.
- Given a live selected market, when funding flips sign or an alert threshold crosses, then the surface becomes frame-ready within one animation frame of store commit and any configured alert fires exactly once per crossing.

## Operational contract

- Persona: Active trader monitoring one market closely while tracking account risk.
- Preconditions: Live market feeds including asset contexts; local alert configuration; audio permission for sounds.
- Success behavior: Stats, liquidation flags, alerts, and book grouping all reflect authoritative live data with per-surface health labels.
- Failure behavior: A degraded context feed marks the stats strip degraded; alerts pause with a visible paused state rather than firing on stale prices.
- Reconnect behavior: Stats and book grouping resubscribe with generation guards; alerts re-arm only after the feed is live and skip crossings that occurred while offline (reported as missed, not fired late).
- Restart behavior: Alert definitions and grouping preferences restore from local storage; no alert fires from restored state until live data confirms a fresh crossing.
- Stale/offline behavior: Stats strip and tape show stale labeling; alert evaluation suspends; the dither stale veil reinforces non-live surfaces.
- Custody expectations: All features are read-only public-data consumers plus local preferences; no new signing paths.
- Latency expectations: Stats and tape updates stay within the receipt-to-store p99 <5 ms and one-frame frame-ready budgets; alert evaluation adds no per-tick allocation on the hot path.
- Telemetry: Record feed health transitions, alert fire/miss counts, and grouping changes without account contents or alert prices.
- Linked tests: stats-context normalization tests, liquidation-flag tape tests, alert crossing/rearm/missed-window tests, book-grouping resubscription identity tests.
- Funded-testnet evidence: Not execution-bearing; requires live-feed evidence that stats/liquidations/alerts track authoritative venue data through reconnect and stale windows on testnet.

- Trade-tape filter slice: a minimum-notional control now filters only received authoritative trades by `price × size`, preserves feed health, and labels a filtered-empty tape distinctly from an unavailable feed.
