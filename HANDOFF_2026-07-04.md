## Part 2 — SITE-WIDE DISPLAY SCALE (MacBook-first) — the big one
Owner: laptop looked blown-up/disproportionate; must scale perfectly on every MacBook, phone, desktop.
The px design targets ~1900px desktops; nothing scaled it down (and per-selector CSS can't reach
ECharts canvas text or engine inline styles). Solution: **body{zoom} scale tiers** —

- `@supports (zoom:0.9)` → tiers: 769–1359px → **0.85** (Air 13/15) · 1360–1512 → **0.9**
  (MBP14/1440/1366) · 1513–1800 → **0.95** (MBP16) · >1800 & ≤768 → 1.0. `--app-zoom` mirrors it.
- Viewport units inside a zoomed body resolve zoom-times too small → **divide by var(--app-zoom)**:
  app shell heights (.app-layout/.sidebar/.main-wrap), search dropdown 60vh, glossary lightbox 92vh,
  player height-fit formulas. (Verified empirically: gBCR = visual px, offset/client/canvas = layout
  px, e.clientX = visual, dvh NOT compensated.)
- **ECharts under zoom**: zrender trusts `e.offsetX` (VISUAL px) against a LAYOUT-px canvas →
  hover/drag land ~15% off (trusted-event verified: zrX 657 vs true 772). Fix:
  `LTUtils.echartsZoomShim(host)` — capture-phase listener shadows offsetX/offsetY/layerX/layerY
  (mouse+pointer+wheel; touch untouched) → zrender falls back to its marker transform solver → exact
  (verified zrX 772.06). Wired at all 3 echarts.init sites (engine renderChart, sim chart, sim equity).
- Coordinate-space fixes from a 6-agent audit: sidebar ctx-menu (clientX/z + innerWidth/z clamps),
  scrollActiveChapterIntoView (delta/z), glossary focus-scroll (delta/z), v2 `_fit` now sizes the
  canvas from clientWidth (layout px — canvas type scales with zoom, no staleness across tier flips),
  `_hitLabel` maps pointer by ratio (this.W/rect.width).
- Compact laptop chrome `@media (min-width:769) and (max-height:960)`: content pads 14/10, banner
  8px/28icon/12mb, watch-link 8px. (Also fixed: the ≤768 banner compaction was DEAD css — base rules
  later in the file won; now `.content-area .module-banner …` prefixed.)

## Part 3 — lesson-player NO-CLIP system (owner: nothing in the player may ever clip or scroll)
Architecture (lessons-v2/renderer.js + player.css):
- **Stage is the hero**: mobile full-width 4:3 always; desktop width caps via the height-fit formula
  `clamp(500px, calc((100dvh/var(--app-zoom) − K − var(--cap-mh)) ×16/9), 960px)` with K=310 (chrome
  ≤960px tall) / **K=348 via a (min-height:961) variant** (airy chrome band 961–1050 was a hole).
- **Caption = the viewport remainder** (`_fitCaptions`): measures every beat's narration at live
  width/font (longhand font copy — the `font` shorthand serializes empty in Safari/FF; measurement
  cached per width|font key), sizes `--cap-mh` to the lesson max, bounded by the REAL remainder on
  mobile (visible-children measurement, NOT scrollHeight — that floored at clientHeight and ratcheted
  the box down while free space sat below) and by preset-aware bounds on desktop (sm 120 / md 160 /
  lg 190).
- **.ltp2--capflow lyric window** when a narration exceeds the box: hidden scrollbar + LIVE edge
  fades (`cap-above`/`cap-below` classes toggled from scroll state — a static fade dimmed the very
  line being narrated); karaoke `_setWord` scrolls the lit line 34px clear of the bottom fade
  (advance-only); at text end the bottom fade lifts so the final line reads at 100%. **Silent paths
  covered**: `_scheduleAuto` pans the caption over the dwell (`_autoScrollCaption`) so narration-off /
  missing-timings / blocked-audio still reveal the tail, and the dwell path now calls
  `_showComplete()` on the final beat (the fanfare overlay was audio-path-only).
- **Concept slides scale-to-fit** (`_fitConcept`): panel re-pinned absolute to the stage (the old
  "relative in-flow + stage scrolls" uniform-player mechanism was the clipping bug — also
  `.ltp2-panel-inner{flex:none}` because a shrinkable flex item hid the true content height, and the
  `is-*` root class now swaps BEFORE the scene renders so measurement sees .is-concept styling).
  Scale floor **0.72**; beyond it → **`.ltp2-panel--window`**: pinned header, user-scrollable bullet
  window (hidden scrollbar) with live lines-above/lines-below fades, `_syncLineWindow` follows the
  reveal (gBCR-based — offsetTop was panel-relative and overshot ~100px), rest state shows the TOP.
- Phone concept compaction (≤560): pmark glyph hidden, kicker/title margins 8/12, panel padding
  14/18, line gap 8. Short phones (≤750 h): module banner + watch-link hidden on player steps
  (`:has(.lesson-wrap--player)`), tighter bar/caption (block placed AFTER the ≤560 block — cascade).
- `.ltp2-done` row hidden ≤768 and 769+/≤960h (it grew the player 42px at completion; the stage
  overlay is the completion cue on every path now).
- Settings: `ltApplyCaptionSize` re-runs `_fitCaptions/_fitConcept` on the live player (stale-fit bug).
